# Shared-city zombie survival

Open **📱 ქალაქის თამაშები** and choose **🧟 ზომბების ათი ტალღა**. The same phone also offers racing, hide-and-seek, tag and player battles. The host creates a lobby, invites 1–5 other players and starts after they accept. Membership is fixed once the match begins.

The cooperative match has ten waves, a five-second starting countdown and ten-second breaks. Each wave increases zombie count, health, speed and damage. After the regular enemies die, one large boss appears. A wave ends only after its boss dies, including wave ten. Boss HP scales with wave and party size; speed and melee damage grow every wave. Heavy zombies start at wave four. The server automatically improves weapon damage/fire rate and changes the weapon name as the team progresses. Breaks restore all teammates to 100 health, including downed teammates. If everyone is down, the match ends. A match also ends without a victory reward if a departing player leaves fewer than two participants, permissions change, or the 15-minute deadline passes. There is no paid upgrade or AI dependency.

Hold the mouse button or **G** for continuous fire, and move the mouse to aim. On touch screens, hold and drag the round fire control to aim while moving with the other thumb; holding/dragging the world also aims and fires. Release, cancel, blur, rotation, menus and backgrounding stop held fire. Each wave grants a distinct weapon: pistol, Beretta, Uzi, MP5, AKS-74U, AK-47, M4, SCAR, PKM and minigun. Every stage increases damage/range and reduces the authoritative cooldown. Player battles share these aiming controls but give both players the same three-hit carbine. The authoritative server checks angles, fire cooldown, distance and walls. Ammunition is unlimited. Teammates and nonparticipants cannot be shot by zombie-mode weapons. Zombies follow and damage only living members of their own match. They do not join vehicle/pedestrian collision lists. Other City visitors receive the same zombie positions and can see the action without joining or becoming targets.

After the server verifies that wave ten and its boss have no remaining zombies, every registered participant still in the match receives **50,000 site coins**, including a downed teammate whose group completed the last wave. Guests can play but cannot receive account money. This is paid once per completed match/account, not once per character or connection. Legitimately completing another match can earn another reward. There is no client reward/kill/wave-completion endpoint. The account balance and receipt use the site's existing save and wallet helpers. Match IDs contain UUIDs and receipts survive restarting the reward service; the last 50 receipts are retained. Active matches themselves are session-only: a server restart cancels them without paying a reward.

`server-city-zombies.js` owns bounded waves, walkable spawning, wall-validated routing, melee, shots and upgrades. `city-world-games-engine.js` owns the invite/membership lifecycle and invokes the reward callback only for a verified zombie victory. `server-city-zombie-rewards.js` deduplicates accounts and records awards in `cityZombieRewards`. The public game renderer, HUD, sound hooks and Georgian guide include the new mode.

Validation: the combined automated suite includes actual server shots through all ten waves, reward persistence/duplicate-account/guest checks, spectator/friendly-fire isolation, real-map navigation, walls, upgrades, wipe/disconnect/deadline cleanup and existing world-game regressions. A local three-client browser check exercises desktop hosting, mobile acceptance/touch aiming, observer-visible zombies, upgrade and result displays, wallet updates and layout. Browser wave progression is accelerated with server-side fixtures after a real touch shot; it is not a full real-time balance/playability study. Production Render deployment and longer live playtesting remain to be checked.

## Shooting implementation

`city-combat.js` shares fixed weapon profiles and circle/ray geometry. Visible upper-body hit areas and muzzle-height rays align aiming and tracers; walls still reject occluded centers. No client-supplied damage, gun or cooldown changes server outcomes. `city-shooting.js` uses a stable fire control outside the rebuilt HUD, local cosmetic shot prediction, bounded outstanding requests, quiet cooldown rescheduling, authoritative reconciliation/hit markers and pointer capture. It never predicts damage or rewards. Zombies interpolate visually between authoritative snapshots. The local sound plays immediately and the sender skips its echoed shot sound. Request IDs are bounded reconciliation metadata only.

Validation includes mouse/G hold and release, simultaneous two-finger joystick/fire dragging, touch aiming and player battles in local browser checks, plus deterministic cadence/latency-cap, geometry and all ten weapon-profile tests. Production network conditions and physical-device feel still need live playtesting.


Weapon appearance: `city-weapon-art.js` draws a distinct pixel silhouette for every server-selected weapon ID (all ten zombie upgrades and the shared battle carbine). Stocks, magazines, barrel length, receivers and attachments change with the gun, rather than only a generic category/color. The existing aim rotation and player interpolation are retained, and every observer uses the same public weapon profile. Browser QA with accelerated server wave fixtures confirms all ten appearances switch on desktop, touch-phone and spectator clients; the contact sheet and phone/desktop screenshots were visually reviewed. This is a visual change only; damage, cooldowns, hit detection and rewards are unchanged.


Hit reliability: zombie targeting uses visible-body circles with feet-based line of sight, so an upper-body sprite overlapping the edge of a building does not make a reachable zombie invulnerable. Actual walls between feet positions still block damage. A shot may reference the exact timestamp of a server-published zombie frame from the previous 300 ms. The server uses only live enemy IDs and its bounded own history, ignoring unknown/stale/future frames and all client damage/weapon fields. This compensates ordinary display/network delay without unlimited rewind. Current-position line of sight, range and cooldown remain authoritative. Bosses use larger visible hit areas and sprites; teammates and spectators receive the same public boss state. Bosses, like normal zombies, never target outsiders.
