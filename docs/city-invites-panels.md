# City invitations and compact windows

Direct games now use the same 175-unit outdoor invitation/acceptance range as the player card. Both players must remain available; blocks, active games, cars, rides and locked activities still prevent a direct match. Failed attempts no longer consume the previous ten-second general invitation delay. An unresolved invitation must be answered/cancelled before another direct invitation can be sent. Expired direct/lobby requests are swept before retrying, even if their timer/tick has not run yet. Client request timeouts and disconnects release the temporary disabled-button state.

`server-city-invite-guard.js` is shared by both production game engines. Explicit refusal blocks the original sender from inviting that recipient again for **60 seconds**, across direct games, Arcade challenges and City lobbies. This is directional and account/name scoped, so another player can still be invited and reconnecting does not reset the minute. Expiration, sender cancellation and disconnect are not refusals. The cooldown is session-memory state and resets on a server restart. Reservation entries prevent pending direct/world invitations from overlapping; a City lobby host can still invite several distinct free players up to the existing six-player limit.

The browser displays the remaining seconds and disables the relevant invite button. The server is authoritative: modifying the browser or switching game modes cannot remove the cooldown. A pending/blocked/busy target remains unavailable for the corresponding reason.

The player card now defaults to name, public conversation, game invitation and a small **⋯** action. Secondary blocking/friendship/emote controls remain under that action. The card and large direct-game, Arcade, Casino, lobby, invitation, dialogue, match-HUD and street-event panels have a **−** minimize control. A small restore dock brings back the same panel. Minimizing is local presentation only: it does not accept/decline an invitation, leave a game, pause a deadline, change a result or stop server gameplay. The phone dimmer is removed while its game window is minimized. Smaller dialogs and invitation cards retain scrolling for their content. Existing books/discovery menus also remain closable/reopenable through their normal controls.

Validation: 82 automated tests, including new direct/cross-mode invitation, refusal/expiry, identity, cancellation and eligibility tests. Browser checks use desktop and emulated portrait/landscape phones, actual player-card and invitation controls, controlled clocks for cooldown expiration, minimize/restore without losing a match, existing zombie touch shooting/rewards, and layout checks. Production and physical-device testing remain pending.
